# 本次目标

判断液态神经网络是否适合当前新洋风电场 `15min-lead`、`46` 台机组联合建模的风速预测场景。

## 实际修改了什么

- 新增本报告，记录本次文献检索和场景适配判断。

## 为什么这样做

问题本质不是“液态神经网络先进不先进”，而是它的归纳偏置是否刚好匹配当前任务瓶颈。

当前任务的核心约束是：

- 固定时间间隔规则采样
- 多机组空间相关显著
- 目标是 `15min` 超短期预测
- 训练在本地/超算离线批处理完成，不是边缘实时控制

因此需要优先判断：液态神经网络擅长解决的问题，是否正是当前任务最难的部分。

## 关键结论

- 结论：`可以试，但不适合作为优先主线模型`。
- 更准确地说，它更适合当：
  - 单机纯时序补充实验
  - 在线残差修正器
  - 小模型/低延迟部署备选
- 不适合当你当前这条线的第一优先大模型路线。

主要原因：

1. 液态神经网络的核心优势不在你当前最大的难点上  
   原始 `LTC` / `CfC` 论文强调的是连续时间动力学、状态自适应、长时依赖和对不规则采样的处理能力。  
   但你现在的数据是规则 `15min` 采样，任务瓶颈更像是：
   - 机组之间的空间耦合
   - 风向/尾流/邻机状态带来的跨机组信息利用
   - 特征工程与功率映射链路设计

2. 你当前任务比“连续时间建模”更需要“空间建模”  
   对新洋 `46` 台机组联合预测来说，`GWNet / AGCRN / MTGNN` 这类图时空模型的结构偏置更直接，和任务本质更对齐。

3. 在风电预测里的公开证据还不强  
   我查到的液态网络在风电场景里的应用是有的，但数量不多，且大多是：
   - 单站点或非图结构
   - 风功率而不是全场多机组风速联合预测
   - 混合分解框架中的一个时序子模块
   说明它“可用”，但还没显示出对你这个场景的压倒性适配优势。

4. 工程复杂度高于你当前最优试验顺序  
   如果现在引入 `LTC/CfC`，你需要额外处理：
   - ODE/连续时间状态更新实现
   - 稳定训练与超参搜索
   - 是否与图结构耦合
   - 与现有基线的公平对比
   这条路成本不低，而预期收益暂时不如继续深挖图时空模型与可派生特征。

## 文献判断摘要

- `Liquid Time-Constant Networks`：适合连续时间序列建模，强调可解释动态和稳定性。
- `Closed-form Continuous-time Neural Networks (CfC)`：在保持连续时间建模思想的同时，训练和推理效率比 `LTC` 更友好。
- 风电相关应用里，确实已经出现基于 `CfC` 的风功率/风速预测工作，但现有证据更像“可尝试的新时序骨干”，不是“已经证明优于图时空路线的主流方案”。

## 面向当前项目的建议

- 若目标是尽快把新洋 `15min` 风速预测做强：
  - 继续优先 `GWNet / AGCRN / MTGNN / ModernTCN`
  - 继续深挖风向、机组朝向、空间上下文、可直接派生特征
- 若目标是补充一条有研究价值的新路线：
  - 先做 `CfC`，不要先做 `LTC`
  - 先做单机轮毂风速纯时序实验
  - 再决定是否扩展到“图编码器 + CfC 时间骨干”的混合结构
- 若目标是在线校正：
  - 液态网络更适合作为轻量残差修正器，而不是替换当前主干

## 当前风险、阻塞和下一步建议

- 风险：
  - 若把液态网络直接当主线，可能会在“结构上很新”但“与主要瓶颈不对齐”的方向上花较多时间。
- 阻塞：
  - 当前公开风电应用证据还不够强，特别是缺少与你完全同构的“多机组图联合风速预测”证据。
- 下一步建议：
  - 若你想试，我建议按这个顺序：
    1. 单机 `CfC` 纯时序基线
    2. 单机 `CfC + 风向/时间` 多变量版
    3. 若单机有明显收益，再评估是否做 `Graph Encoder + CfC`
