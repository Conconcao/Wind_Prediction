# 为什么这样做

- 是否能做“更强的时空联合建模”，关键不在于有没有方向字段名，而在于：
  - 方向数据是否覆盖全部机组；
  - 是否存在大面积缺失；
  - 时间覆盖是否足够长；
  - 现有代码是否已具备动态图接口。

# 结论

- 可以做更强的时空联合建模。
- 而且现有 `GWNet` 代码已经具备动态图方向支撑接口，真正缺的是“把这份 `15min` 方向数据接入当前 `1min` 风速 store”。
- 最合理的方向增强实验不是直接依赖 `1min` 风向，而是：
  - 保留 `1min` 原始 `ws` 历史序列；
  - 用 `asof/backward` 方式把最近一条 `15min` 方向快照对齐到每个分钟级 origin；
  - 在 `GWNet` 中开启 `dynamic_directional_support`。

# 当前风险、阻塞和下一步建议

- 若接入方向数据，方向增强实验将不再覆盖 `2023-07-03` 到 `2023-12-01` 这段早期样本。
- 因此方向增强结果应单独作为“重叠有效窗上的对照实验”，不能与当前全窗 `ws-only` 结果直接混为一谈。
- 推荐下一步：
  - 新建一条淮安 `1min ws + 15min direction` 的 overlap-only 实验链路；
  - 先做 `GWNet + dynamic_directional_support`；
  - 再做一个 `TFT/GRU + direction features` 作为纯时序对照。
